# v1.0.17 검증

## 연역 엔진 및 배틀 회귀 검증

n- `node tests/hint-dock.cjs`: 8개 화면 크기에서 힌트 카드가 보드와 겹치지 않는지, 정답 채우기 버튼이 화면 안에서 눌리는지 검사합니다.
n- `node tests/features.cjs`: 자동 메모, 케이지 색상, 완성 애니메이션, 볼륨·진동 설정, 연속 기록·업적, 배틀 채팅(모의 서버), 6버튼 툴바 폭을 검사합니다.
n- `node tests/generation-quality.cjs`: 2칸 케이지 비율 상한(60%)과 쉬운 기법 우선 힌트, 힌트 정답 일치를 검사합니다.

- `node tests/room-recreate.cjs`: 방을 연속으로 다시 만들어도 늦은 /api/close가 새 방을 닫지 않는지 검사합니다.

- `node tests/human-hint.cjs`: 퍼즐을 사람 수준 힌트만으로 진행하며 정답 일치, 문장 중복 없음, 설명 길이를 검사합니다. `DIFFS=easy,hard`로 난이도를 지정할 수 있습니다.
- `node tests/room-code.cjs`: 같은 Wi-Fi에 방이 여러 개일 때 4자리 코드로 맞는 방을 찾는지, 없는 코드·정원 초과 안내를 검사합니다.
- `node tests/toast.cjs`: 안내 메시지가 보드·키패드·툴바를 가리지 않는지 검사합니다.

- `node tests/tablet-layout.cjs`: 태블릿 영역 합산 캡슐 숨김, 배틀 보드 아래 여백, 일반·배틀 합계 숫자 동일, 한 칸 케이지 강조를 검사합니다.

- `node tests/hub.cjs`: 설정 화면 제목(태블릿·모바일)과 업적의 어워드 통합을 검사합니다.

- `node tests/cell-overlap.cjs`: 합계 숫자와 입력 숫자가 겹치지 않는지 검사합니다.
- `node tests/auto-notes-toggle.cjs`: 자동 메모 켜기·끄기와 직접 적은 메모 복원을 검사합니다.

- `node tests/polish.cjs`: 세 가지 테마의 홈 화면, 키보드 선택, 참가 오류 표시, 대화상자 초점 순환·복귀와 코드 복사를 검사합니다.

- `node tests/deduction.cjs`: 고정 시드 60개 퍼즐에서 모든 후보 소거의 정답 보존, Naked/Hidden Pairs·Triples, 교차 소거, 확장 45 규칙 실행, 추론 의존성 누락 여부, 모순/다중 후보에서 힌트 거부를 검사합니다. 모든 난이도의 생성 결과는 유일해와 81칸 연역 완성을 통과해야 합니다.
- `node tests/battle.cjs`: 휴대폰/태블릿 11개 뷰포트에서 스크롤 크기, 버튼 터치 가능 여부, 정사각 보드, 영역 합산 표시의 겹침을 검사합니다. 기권 주체별 결과, 결과 중복 기록 방지와 응답 유실 후 재시도도 검사합니다.
- `node tests/battle-network.cjs`: `JAVA_TEST_BIN`과 `JAVA_TEST_CLASSES`를 지정하면 실제 Java 서버와 브라우저 두 개로 방장/게스트/동시 기권을 검사합니다. `BattleServerSmoke.java`를 서버 소스와 함께 먼저 컴파일하세요. 18888 포트를 테스트에 사용합니다.
- `PLAYWRIGHT_MODULE` 또는 `NODE_PATH`로 별도 설치된 Playwright를 지정할 수 있습니다. 브라우저 검사는 Windows Edge를 사용합니다.
- `experience.cjs`는 방 생성 후 시작 버튼에서 퍼즐을 만드는 현재 흐름과 별도 Worker의 연역 엔진 로딩을 검사합니다.

힌트 단계 수는 후보 소거의 의존성을 포함한 실제 증명 경로 길이입니다. 찾아낸 경로들 중 짧은 경로를 우선하며, 가능한 모든 증명의 전역 최단성을 보장하는 완전 탐색은 하지 않습니다. 후보가 하나로 확정되지 않으면 정답판 참조나 MRV 추측으로 힌트를 만들지 않습니다.

확장 45 규칙은 같은 종류의 서로 겹치지 않는 1~3개 행/열/박스 묶음을 사용합니다. 경계가 12칸 이하인 합 제약에 범위 소거를 적용하고, 미확정 경계가 4칸 이하이면 합을 만족하는 배치로 추가 소거합니다. 배치 열거 상한에 도달하면 그 불완전한 결과로 후보를 제거하지 않습니다.

구조 템플릿은 숫자를 배치하기 전에 연결된 1/2/3칸 영역을 정하며 무작위 분할과 번갈아 시도합니다. 숫자 중복·유일해·연역 완성 검증을 생략하지 않습니다. 이는 생성 성공률을 돕는 휴리스틱이며 기존 대비 속도 향상 배율을 보장하지 않습니다.

실제 Android 기기의 WebView, 시스템 글꼴 확대 및 Wi-Fi 환경은 별도 실기기 확인 대상입니다.

- `BattleServerSmoke.java`: 순수 JDK에서 BattleServer와 함께 컴파일 후 실행합니다. 18888 포트로 참가, 공통 규칙 전달, 한글 JSON 전송, 시작/종료, 서버 재시작을 검사합니다.
- `experience.cjs`: Playwright를 설치한 환경에서 `node tests/experience.cjs`로 실행합니다. `BROWSER_PATH`로 Chromium 기반 브라우저 경로를 지정할 수 있습니다.
- 브라우저 검증은 AndroidBridge를 모의 구현합니다. 실제 Android WebView 및 두 휴대폰 간 네트워크 검증을 대체하지 않습니다.

새 숫자 코드는 IPv4 전체 주소를 10자리 숫자로 표현하고 2자리 검증값을 붙입니다. 4자리씩 띄어 표시하며 입력 시 공백과 하이픈을 허용합니다. IP 직접 연결이 가능한 LAN에서 주소 대역이 달라도 같은 호스트를 찾습니다. NAT 통과나 인터넷 중계 기능은 포함하지 않습니다. 기존 1~3자리 코드는 같은 /24 주소 대역에 한해 호환됩니다.

대전 진입은 퍼즐을 생성하지 않습니다. 사용자가 방 준비를 누르면 Worker에서 생성하며, 취소/옵션 변경 시 작업을 종료합니다. 검증 실패한 임의 퍼즐은 반환하지 않습니다. 방 생성 시 목숨·힌트 규칙을 확정하여 퍼즐과 함께 전달하고 대전 중 변경하지 않습니다. 효과음·표시 옵션은 각 기기의 환경 설정입니다.
