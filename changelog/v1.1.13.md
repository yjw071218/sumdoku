# Sumdoku v1.1.13

- 배틀 결과를 서버에 확정합니다. 기존에는 기권만 서버에 기록되어, 상대 기기가 마지막 수나 진행 상황을 받기 전에 경기가 끝나면 한쪽(턴제에서는 승자)에게 결과창이 뜨지 않을 수 있었습니다. 이제 턴제 점수 판정, 레이스 완성, 서바이벌 탈락, 타임어택 시간 종료, 음수 점수 종료 결과를 승자 정보와 함께 서버에 기록하고, 상대 기기는 서버 결과로 결과창을 표시합니다. 재대결로 방이 초기화되어도 직전 결과를 받을 수 있습니다.
- 4자리 방 코드 접속 안정성 개선: 배틀 로비에 들어가면 앱의 모든 연결을 Wi-Fi에 고정해, 인터넷 없는 Wi-Fi에서 Android가 모바일 데이터로 연결을 보내 방을 찾지 못하던 문제를 막습니다. 방 탐색은 실패 시 자동 재시도(네이티브 2회 + WebView 스캔)하고, 참가 요청도 최대 3회 재시도합니다. 홈으로 돌아가면 고정을 해제합니다.
- 4자리 코드로 방을 찾지 못하던 문제 수정(IP 직접 입력은 되는 경우): 주소 스캔이 주소당 0.18초만 기다려 Wi-Fi 절전으로 응답이 늦은 방장 기기를 건너뛰었고, 스캔이 먼저 끝나면 브로드캐스트 응답을 기다리지 않고 실패를 반환했습니다. 같은 /24 대역은 1.2초(재확인 2.5초), 코드 확인은 최대 2~2.5초까지 기다리고, 브로드캐스트는 3초 동안 0.3초 간격으로 재전송하며 끝까지 응답을 기다립니다. 방장 기기는 방이 열려 있는 동안 Wi-Fi 저지연 잠금으로 절전을 막습니다. 방을 못 찾을 때의 최대 대기는 약 7초입니다.
- 모바일 데이터가 켜져 있으면 배틀 로비에서 끄라는 경고를 표시합니다(8개 언어).
- 공유기의 기기 간 통신 차단(AP 격리)은 앱에서 우회할 수 없습니다. 이 경우 휴대폰 핫스팟을 사용해 주세요.

검증: battle-result-sync(실제 Java 서버, 상대 턴 로그 차단 상태에서 턴제 승/패/무승부·레이스·서바이벌 탈락·타임어택 6개 시나리오 양쪽 결과 표시), battle-modes, battle-wifi, i18n-coverage, settings-modal-safe-area, battle-layout-safe-area, TurnModeSmoke, BattleServerSmoke, RoomDiscoverySmoke, SlowHostProbeSmoke(0.9초 지연 방장: 기존 코드 실패 재현, 수정본 통과) 통과. assembleRelease 성공.
Wi-Fi 고정과 모바일 데이터 감지는 브라우저 검사로 확인할 수 없어 실기기 확인이 필요합니다.
