# Sumdoku v1.1.15

### 1. 모바일 데이터 오탐지 수정 (핸드폰에서 Wi-Fi만 켰을 때 경고 뜨는 문제)
- 최신 LTE/5G 스마트폰에서 VoLTE/IMS 통화용 셀룰러 망이 상시 연결되어 있어, 모바일 데이터를 껐음에도 `TRANSPORT_CELLULAR` 인터페이스 감지로 인해 "모바일 데이터가 켜져 있습니다" 경고가 뜨던 현상을 수정했습니다.
- Android 시스템 설정의 모바일 데이터 토글 스위치 상태(`tm.isDataEnabled()`, `Settings.Global.mobile_data`)를 최우선으로 확인하고, 셀룰러 네트워크도 인터넷 데이터망(`NET_CAPABILITY_INTERNET`)이 활성화된 경우에만 감지하도록 개선했습니다.
- Wi-Fi 전용 태블릿이나 유심이 없는 기기뿐 아니라, 스마트폰에서 모바일 데이터를 끄고 Wi-Fi만 켠 상태에서도 정상적으로 경고 없이 배틀을 진행할 수 있습니다.

### 2. 다국어(7개 언어) 번역 전면 보강 및 한국어 잔존 텍스트 완전 제거
- `localize-ui.js`의 DOM 순회에서 `textarea` 플레이스홀더 번역이 제외되던 문제를 수정했습니다.
- 토스트 팝업 메시지(`showToast`)가 다국어 번역 사전(`window.I18N.text`)을 거쳐 출력되도록 수정했습니다.
- `refinements.js`의 이모지 치환 시 텍스트 노드가 분리되어 번역 키 매칭에 실패하던 현상을 해결했습니다.
- 배틀 모드 카드/설명, 배틀 HUD(내 턴, 상대 턴, 생존 시간, 상대방 스도쿠 판 등), 배틀 결과 창(무승부, 음수 승리, 시간 초과, 탈락, 스피드 완주), 상태바 툴팁, 메모장 플레이스홀더, 통계/전적 화면 등 7개 언어(영어, 일본어, 중국어 간체/번체, 스페인어, 프랑스어, 독일어) 번역을 완벽 보강했습니다.
- 실제 앱 전체 화면/모달 라이브 순회 검사(`find-all-untranslated-live.cjs`)에서 한국어 잔존 0건을 확인했습니다.

### 3. 일일 도전 연속 기록 칩 및 다크 모드 가독성 보정
- 일일 도전 카드의 연속 기록 문구를 "최고 연속 N일 · 다시 도전"으로 직관화하고, 파란 카드 위에서 잘 보이도록 칩 색상 및 자동 줄바꿈을 적용했습니다. 영어 등 번역 오류("Best in N days")도 수정했습니다.
- 다크 모드 가독성 수정: 일일 도전 화면 제목, 하단 탭 글자, 한 칸 케이지 합계 숫자, 선택된 메뉴/모드 버튼, 배틀 메뉴 설명 텍스트 색상을 대비 4.5:1 이상으로 조정했습니다.

### 4. 버튼 속 깨진 기호(`¡`) 수정
- 일부 버튼에서 이모지가 원치 않는 정보(info) 아이콘(`¡` 형태의 SVG)으로 강제 변환되던 문제를 수정했습니다.
- 매핑되지 않은 이모지는 SVG로 변환하지 않고 원본 텍스트/이모지를 온전히 보존하도록 개선했습니다.
- 매핑되지 않은 이모지만 있는 텍스트는 아예 다시 처리하지 않아, 화면이 멈추는 무한 반복을 막았습니다.
- 리플레이 컨트롤 버튼(처음, 이전, 재생/일시정지, 다음, 끝, 닫기)에 고화질 커스텀 SVG 아이콘을 지원합니다.

### 5. 배틀 리플레이 컨트롤 바 모바일 최적화 배치
- 배틀 리플레이 재생 시, 조작 컨트롤 바(이전, 재생, 다음, 슬라이더)를 상대 보드 아래가 아닌 **내 보드 바로 아래(상대 보드 위)**에 배치하여 스마트폰 한 손 조작성을 대폭 개선했습니다.

### 6. 배틀 리플레이 상대 보드 정밀 렌더링 지원
- 상대방 스도쿠 보드에 3×3 굵은 박스 격자선, 케이지 점선 테두리(`.cage-inset-border`), 케이지 합계 배지(`.cell-cage-sum`)를 추가하여 퍼즐 구조를 한눈에 알아볼 수 있도록 했습니다.
- 배틀 중 상대방의 실시간 메모(notes) 데이터도 동기화하여, 리플레이에서 상대방이 어떤 후보 숫자를 적고 지웠는지 미니 메모 그리드로 확인할 수 있습니다.

### 7. 스피드 레이스 & 타임어택 목숨 무한(`0 / ∞`) 및 오답 큰 감점
- 스피드 레이스(`race`) 및 타임어택 점수전(`score` / `timeattack`)에서는 오답을 적어도 탈락하지 않고 목숨이 `0 / ∞`로 표시됩니다.
- 오답 입력 시 목숨 소진 대신 **큰 감점(첫 오답 -200점, 이후 오답마다 100점씩 증가, 최대 -600점)**과 실수 횟수 카운트가 적용되어 찍기를 막고, 실수 때문에 게임이 중단되지 않고 끝까지 레이스를 펼칠 수 있습니다.

검증: verify-replay-and-battle (아이콘 깨짐 0건, 리플레이 바 위치, 상대 보드 격자/합계/메모 렌더링, 타임어택 및 배틀 레이스/점수전 무한 목숨/누적 감점 검증 완료), i18n-coverage (7개 언어 누락 0건), status-bar-live, settings-modal-safe-area 통과. assembleRelease 빌드 성공. 실제 기기 확인은 별도입니다.


### 8. 스피드 레이스 점수제 승패
- 한 명이 퍼즐을 완성하면 경기가 끝나고, 완성한 사람에게 기존 완성 보너스(속도·퍼펙트·노힌트)에 더해 **+3,000점 완주 보너스**를 줍니다.
- 먼저 완성한 사람이 아니라 **최종 점수가 높은 사람이 승리**하며, 같은 점수면 무승부입니다. 오답을 많이 내고 먼저 완성하면 질 수 있습니다.
- 승패와 종료 이유(race)를 서버에 기록해 두 기기에 같은 결과가 표시됩니다.

### 8. 스피드 레이스 점수제 승패
- 한 명이 퍼즐을 완성하면 경기가 끝나고, 완성한 사람에게 기존 완성 보너스(속도·퍼펙트·노힌트)에 더해 **+3,000점 완주 보너스**를 줍니다.
- 먼저 완성한 사람이 아니라 **최종 점수가 높은 사람이 승리**하며, 같은 점수면 무승부입니다. 오답을 많이 내고 먼저 완성하면 질 수 있습니다.
- 승패와 종료 이유(race)를 서버에 기록해 두 기기에 같은 결과가 표시됩니다.
- 승패는 **서버가 한 번만 판정**합니다. 완주자의 종료 요청이 도착한 순간 서버에 기록된 두 사람의 점수로 승패를 정하고, 두 기기는 그 결과와 점수를 그대로 표시합니다. 서버의 진행 상황 기록과 종료 처리를 동기화해, 두 사람이 거의 동시에 완성해도 먼저 도착한 종료만 인정합니다(이전에는 두 기기 모두 승리로 표시될 수 있었습니다).
- 스피드 레이스에서는 점수가 바뀔 때마다 0.6초 주기를 기다리지 않고 즉시 서버에 점수를 보내, 완주 직전에 상대가 얻은 점수도 판정에 반영됩니다. 네트워크 지연(수십 ms) 안에 입력한 점수는 반영되지 않을 수 있습니다.
- 서버 연결이 끊겨 종료 요청이 실패하면 각 기기가 마지막으로 받은 점수로 예비 판정합니다.

검증(추가): race-two-device(실제 Java 서버 + 브라우저 2개, 지연 30~90ms 모의, 일반 완주·완주 0.3초 전 상대 역전·동시 완주 각 3회 = 9회 모두 두 기기 결과와 서버 점수 일치; 수정 전 코드에서는 동시 완주 시 두 기기 모두 승리 표시 재현), race-score-win(서버 실패 시 예비 판정), battle-result-sync, battle-network, BattleServerSmoke, TurnModeSmoke, battle-modes, verify-replay-and-battle, i18n-coverage 통과.
